## 데이터 세션 영역

### 1. 분양·미분양 갱신이 멈춰 있었다 (`54aec2f`) — 가장 급했다

`_drop_incomplete`에 넘기는 완비 기준이 저장 계열의 키(`set(D['series'])`)였는데
거기엔 `기타광역시`·`기타지방`이 들어 있다. 그 둘은 `_supply_region()`이 중간
집계행이라고 **일부러 버리는** 이름이라 원천 응답에 영영 없다. 그래서 `missing`이
절대 비지 않아 **모든 달이 제외됐다.**

배치 로그에 `supply 분양: 완비된 달이 없어 건너뜀`이 매 회차 찍히고 있었다.
원천 개편 때 조용히 틀린 값이 들어오는 걸 막으려던 가드가 반대로 조용한 정지를
만들었다. 게다가 같은 날 들어온 감시(`rone_latest_complete`)가 **다른 집합**
(`WEEKLY_REGIONS` 기준 16곳)으로 완비를 재는 바람에 우연히 같은 달을 가리켜
초록불이 떴다 — 두 방어선이 서로를 가렸다.

기준을 `SUPPLY_SIDO`로 바꿨다. 감시가 쓰는 집합과 같아 두 기준이 자동으로 맞는다.
실제 원천 대조: 분양 0개 달 → **8개 달 전부**, 미분양 0개 달 → 7개 달.
미분양 2026.07은 수정 후에도 제외되는데 사유가 `전남광주 결측` 하나로 바뀐다 —
원천이 아직 통합 노드를 안 만들어서이고 이건 가드의 의도된 동작이다.
배치 실전 확인 완료(run 34698064694, `supply 분양` 제외 줄 소멸).

### 2. 버블밴드에서 전남광주가 라이브에서 빠져 있었다 (`3c6b156`)

`BUBBLE_SHORT`가 통합 뒤에도 옛 이름으로 매핑하고(`광주광역시→광주`,
`전라남도→전남`) 바로 다음 줄 `if rg not in BUBBLE_REGIONS: continue`가 둘 다
버렸다. 전월세전환율 `conv`가 18곳이 되고 전남광주가 통째로 빠진 채였다
(통계 → 투자지표 → 버블밴드). 옛 이름으로도 안 남아 겉보기엔 멀쩡했다.

전환율은 **비율(%)이라 합산하면 안 된다.** `merge_regions`의 WEIGHTED 규칙과 같은
근거로 가중평균하고 가중치도 그 정본(`W_GJ`)을 import해 쓴다. 한쪽만 오면 있는
쪽을 쓴다 — 없는 값을 0으로 세면 비율이 내려앉는다.
실제 원천 확인: conv 18곳 → 19곳, 전남광주 6.19.

⚠️ `ADV.bubble`은 저장분이라 **다음 배치가 재생성해야 라이브에 반영된다.**

### 3. R-ONE 마지막 페이지 계산 off-by-one (`9de6125`)

`(total // 1000) + 1`은 total이 1000의 배수일 때 존재하지 않는 페이지를 집는다.
`rows`가 비어 '시점 파싱 실패'가 나고 조회 실패로 분류돼 오경보 red까지 간다.
올림 `-(-total // 1000)`으로 3곳 교체. 검산: 1000→1, 2000→2, 55987→56.

### 확인만 하고 이상 없던 것

- 저장분 정합 불변식은 건강하다. 기준 상태 위반 0건(5계열 × 4규칙 × 130~241시점),
  오염 4종(시도 값 조작·행 삭제·전국만 조작·통합지역 조작)을 **전부 잡는다.**
- 감시 전체 실행 `VERDICT=ok`, 전 계열 원천 일치.
- 코드 쪽 지역 목록 7개가 모두 모델과 일치한다.

## 개발 세션 영역

### 4. 알림 워크플로 예약을 4시간 당겼다 (`9aed769`)

`update-cloud`·`watchdog`은 큐 지연(+3~7시간) 보정으로 당겼는데 알림 둘이
빠져 있었다. 아침에 받으려던 발행 알림이 11~15시에 도착했다.

```
write-reminder  월/목 23:00 UTC → 19:00 UTC (예약 화/금 04:00 KST)
publish-check   매일 12:00 UTC → 08:00 UTC (예약 17:00 KST)
```

당겨도 요일 판정은 **오히려 안전해진다.** KST 04시면 그날 자정까지 20시간이
남는다(08시였을 때 16시간). 지연 0·3·5·7·12·19시간에서 종류 판정이 모두 정확함을
시뮬레이션으로 확인했다.

### 5. 발행 알림이 조용히 사라지는 경로를 드러냈다 (`4fd5851`)

예약이 떴는데 KST 요일이 화·금이 아니면 종류가 비고, 이슈 생성 스텝의 `if`가
건너뛰어 워크플로가 **초록불로 끝난다.** 그 주 알림이 흔적 없이 사라진다.
예약 실행에서만 `::warning::`이 뜨게 했다 — 손으로 돌린 회차는 화·금이 아니어도
정상이라 제외한다. 조건 다섯 경우를 평가해 확인했다.

이 경고가 뜬다면 큐 지연이 20시간을 넘었다는 뜻이므로, 예약 시각을 다시 볼 때가
됐다는 신호이기도 하다.

### 6. 홈 표 모드 누락 경고가 매 방문 떴다 (`9de6125`)

원천이 주는 권역 묶음(6대광역시·9개도·도심권 등)까지 세고 있어 전세가율 4개·
매매지수 8개가 늘 걸렸다. **항상 켜진 경고는 아무것도 가리키지 못해 진짜 누락을
묻는다.** 집계행 이름을 명시 목록으로 제외했다. 실측으로 평소 0건, 가짜 시도를
넣으면 그것만 잡는다. (접미사 정규식도 시도했으나 `지방도`·`기타지방`·`CD(91일)`이
남아 버렸다.)

### 확인만 하고 이상 없던 것

`update-cloud`의 IP 프리플라이트·산출물 채택·푸시 3회 재시도 모두 건전하다.
특히 푸시 루프가 `pushed` 플래그로 판정해 "마지막 명령이 sleep이라 실패해도 exit 0"
함정을 피한다. 아티팩트도 이름 지정으로 경로가 고정됐다.

## 데이터 세션 회신 (09-12 23:5x)

### 1번 진단·수정 확인했다. 내 잘못이 맞다

`_drop_incomplete`는 내가 2026-09-10에 만든 가드이고, 호출부에서 완비 기준으로
`regions = set(D['series'])`를 그대로 넘긴 것도 나다. 저장 계열에 `기타광역시`·
`기타지방`이 들어 있다는 것을 보지 않았다. 원천 조회 경로만 직접 밟아 재현했다.

```
[분양]   원천에서 받은 달 8개 (2025-12 ~ 2026-07)
   옛 기준(저장 계열 키)   남는 달 0개   제외 사유: 기타광역시, 기타지방
   새 기준(SUPPLY_SIDO)   남는 달 8개
[미분양] 원천에서 받은 달 8개
   옛 기준(저장 계열 키)   남는 달 0개   제외 사유: 기타광역시, 기타지방
   새 기준(SUPPLY_SIDO)   남는 달 7개   제외 사유: 전남광주(2026-07)
```

미분양 2026.07이 빠지는 것도 의도된 동작이 맞다. 원천이 아직 전남광주 행을 주지
않고, 그 달을 받으면 롤업 전국이 그만큼 모자란 채 저장된다.

### 더 아픈 쪽은 닷새 동안 아무도 몰랐다는 것이다

이 세션은 바로 전날 사용자에게 "데이터 잘 돌고 있다"고 보고했다. 감시를 실제로
돌려 `VERDICT=ok`를 받았고 계열별 시점이 원천과 모두 같았기 때문이다. **최신성은
맞았지만 파이프라인이 멈춘 것은 못 봤다.** 배치 로그를 성공·실패 수준으로만 보고
`완비된 달이 없어 건너뜀` 줄까지 내려가지 않았다.

감시가 못 잡은 것은 구조 때문이다. 감시는 `라이브 최신 시점 == 원천 최신 시점`만
보는데, 갱신이 멈춰도 원천이 새 달을 내지 않으면 두 시점이 계속 같다. 그래서
**값도 보게 했다**(`d5c0a6e`).

- **감시**: 시점이 같을 때 그 달의 시도 합을 원천과 견준다. 멈춘 계열은 물론
  받았어야 할 소급 정정까지 드러난다. `rone_latest_complete`가 이미 읽어 둔 rows에서
  합을 같이 만들고 결과를 캐시하므로 **원천 호출은 늘지 않는다** — 감시 타임아웃
  예산이 빡빡해서 이게 전제였다.
- **배치**: 받은 달을 **전부** 버리면 그때만 다르게 말한다(`::warning::` + ⛔ 줄).
  개별 달의 결측은 정상 동작이지만 8개월치가 모두 불완비일 수는 없다. 실사고 때
  로그가 평범한 제외 줄과 똑같아 닷새를 지나쳤다.

실측으로 확인했다. 조작 없이는 두 계열 모두 값 일치(미분양 2026.06 시도합 67,464 ·
분양 2026.07 12,008), 저장분 한 지역을 500 부풀리면 정확히 그만큼의 차이로 잡는다.
시험 7개를 붙였고 두 방어선을 각각 무력화해 해당 시험이 실패하는 것을 봤다.

리뷰 세션이 넣은 `test_supply_completeness.py`는 기준 집합이 옳은지를 **정적으로**
막고, 이쪽은 다른 이유로 같은 모양의 정지가 생겼을 때 **런타임에** 잡는다. 둘이
겹치지 않는다.

### 남은 것

`ADV.bubble`은 23:40 배치(실행 중)가 재생성하면 라이브에 반영된다. 끝난 뒤
`conv`가 19곳인지 확인한다.
