# 시도 단위 재편 + 공급·가격 통합표 설계

작성 2026-08-06. 근거 실측은 `memory/agongmap-future-supply-source.md`.

## 왜 바꾸나

지금까지 미래 공급을 건축HUB **준공예정(sched)** 으로 세고 있었는데, 그건 인허가만 받고
삽을 안 뜬 계획이다. 2028년 입주예정 363,701세대 중 **착공한 건 0건**이다(데이터 누락이
아니다 — 준공된 단지의 착공일 보유율은 연도별로 전부 100%). 착공 기반 추정과 견주면
**1.29~1.68배 과대**였고, 이것이 "서울이 균형으로 나온다"의 최종 원인이었다.

기준표은 미래를 인허가가 아니라 **입주물량 3년치**로 본다. 그리고 기준표 적정물량 상수 합계
(연 372,800호)는 국토부 아파트 준공 실적 평균(연 325,816호)의 **0.87배**로, 애초에
국토부 통계 스케일에 맞춰진 값이다. 우리가 어긋나 있던 축을 여기에 맞춘다.

**리드타임 3년 · 전환율 0.958은 실측값**(전국 연간, 12개월 완비 연도만). 변동계수 0.138로
k=2(0.208)·k=4(0.239)보다 뚜렷이 안정적. 착공·준공은 같은 통계표의 두 열이라 오차가
같은 방향으로 걸린다.

⚠️ KOSIS가 값 0을 '-'로 주기 때문에 결측처럼 보이지만 **진짜 0이다**. 시도 합계 ÷ 전국이
모든 연도에서 정확히 1.00. 대구 2023년 하반기 착공 0은 사실(미분양으로 착공 중단).
**결측을 건너뛰지 말고 0으로 다룰 것.**

## 지역 구성 (20곳)

`전국 · 수도권 · 지방` 3개 집계 + 17개 시도.

- 생활권 31곳 → 폐기. **시군구 단위는 완전 삭제**(페이지·URL 모두, 리다이렉트도 두지 않음).
- 건축HUB 파이프라인 전체 제거 대상: `fetch_hub_permits.py`, `reseed_campaign.py`,
  `merge_hub_shards.py`, `rebuild_hub_projects.py`, `hub_permits.json`, `update-hub` 워크플로.
- 안분은 수도권 3분할과 세종·제주 추정 두 곳뿐. `zone_share`·`POOLS`는 불필요.

## 통합표

행 = 기간, 열 = 20개 지역, 칸 = 공급량(세대).

**기간 표기**: 월 `17.1` / 분기 `17Q4` / 연 `2017`. **기본 분기.**

**칸 배경색** — 상승·부족은 붉게, 하락·과잉은 푸르게.
- 과거 칸: **세로 3등분**, 왼쪽부터 매매 / 전세 / 월세. 스케일 ±2%가 만색.
- 미래 칸: **단색**, 적정물량 대비 부족분. 100%p 차이가 만색.
- **최소 진하기 0.13** — 값이 정확히 0.00일 때만 무색. 흰 칸은 오류처럼 보인다.
- 현재 시점(마지막 실적 분기와 첫 미래 분기 사이)에 **3px 굵은 줄**.

**토글**: 기간(월/분기/연), 적정물량 대비 보기(숫자를 % 로 전환).

### 알아둘 것

- **전세는 매매와 상관 0.92**로 거의 겹친다. 월세가 0.66으로 가장 독립적이라 3등분의
  정보량은 사실상 매매+월세에서 나온다. 2등분으로 줄일 일이 생기면 매매+월세를 남길 것.
- 연 모드의 **2026년은 실적 2분기 + 추정 2분기 혼합**이라 별도 표시가 필요하다.
- 2029년은 2분기까지만. 분기가 지날 때마다 한 칸씩 늘어난다.
- 미분양은 순위 산식에 넣지 않는다(결과값이라 부호가 반대·이중계상). 대구처럼 미분양이
  많은데 '부족'으로 나오는 지역은 미분양 수치를 **표시용으로 함께** 보여줘 오해를 막는다.

## 산식

기존 러닝재고 골격은 유지하되 입력만 교체한다.

```
I_now = Σ_{과거 16분기} (준공 − 멸실 − 적정)
미래공급 = Σ_{k=1..H} 착공(k−12분기) × 0.958
누적순부족 = 적정 × H − 미래공급 − I_now
```

H는 착공 자료가 닿는 데까지(현재 11분기). `FUT_HORIZON` 16 → 가용 분기 수로 동적 결정.
5등급 판정(`GRADE_CUTS` 1.5/1.0/0.5/-0.5)은 그대로.
