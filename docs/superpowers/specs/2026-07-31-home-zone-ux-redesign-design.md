# 홈·존 페이지 UX 재기획 설계 (2026-07-31)

## 배경과 목표

사용자 진단: 정보 우선순위 불분명 · 이해 난이도 높음 · 페이지 간 흐름 단절 · 행동 유도 부재 — 네 가지 전부.

결정된 방향:
- **타깃**: 내집 마련 실수요자 (30~40대, "지금 사도 되나, 어디가 안전한가", 부동산 지식 얕음)
- **첫 화면**: 내 지역 먼저. 전국 순위는 그 아래로 강등
- **결론 형태**: 등급 판정 + 한 줄 해석. 숫자는 근거로
- **CTA**: 내 지역 저장 → 재방문 시 내 지역 카드 + 지난 방문 대비 변화 (유일한 CTA. 공유·비교·퀴즈 연결은 이번 범위 아님)
- **접근**: A안 — 기존 페이지 재구성. 페이지 신설 없음

## 1. 등급 판정 규칙

**기준값**: `순부족 ÷ 4년 필요량` = `tot ÷ (refq × share × 16)`. 모델이 이미 쓰는 두 값의 비율 — 새 계산 없음.

| 등급 | 컷 | 2026-07 해당 | 한 줄 해석 |
|---|---|---|---|
| 매우 부족 | ≥150% | 8곳 | 앞으로 4년, 필요한 집이 크게 모자랍니다 |
| 부족 | 100~150% | 9곳 | 공급이 수요를 못 따라갑니다 |
| 다소 부족 | 50~100% | 15곳 | 부족하지만 심하진 않습니다 |
| 균형 | −50~50% | 5곳 | 필요한 만큼 들어오고 있습니다 |
| 공급 여유 | <−50% | 7곳 | 입주가 몰려 있어 세입자·매수자에게 유리한 시기가 옵니다 |

원칙:
1. **"공급 기준 · 가격 예측 아님" 캡션을 등급 옆에 항상 표기.** 근거: 2026-07-31 검증 — 금리 급변 구간에서는 공급→가격 신호가 실측으로 안 보인다 (memory/agongmap-index-calibration.md)
2. **절대 컷 고정.** 상대평가는 전국이 과잉이어도 같은 수의 "부족"을 만들어 왜곡. 컷은 코드 상수 `GRADE_CUTS = [1.5, 1.0, 0.5, -0.5]`. 재조정은 명시적 결정으로만
3. **등급 함수는 이중구현 미러 대상.** Python(`make_zone_pages.grade()`)·JS(scCalc 옆 `scGrade()`) 양쪽 + `check_dual_calc.py`가 등급까지 대조
4. 색은 기존 발산 막대 색 토큰 재사용 (부족=적계열, 여유=청계열). 새 색 도입 없음 — 디자인 방향 '원부' 유지

## 2. 홈 구성

### 첫 방문 (localStorage에 지역 없음)

```
① 히어로: "우리 동네 아파트, 앞으로 모자랄까 남을까"
   [지역 선택기] 시도 선택 → 생활권 칩 (2탭 이내)
   아래 작게: "지금 전국 44곳 중 17곳이 공급 부족" (등급 집계 한 줄)
② 전국 한눈에: 발산 막대 순위를 5등급 구간 헤더로 그룹핑
③ 이번 주 시세 지도 (기존 유지, 위치 강등)
④ 퀴즈 유도 (유지)
⑤ 사이클 리포트 + 신뢰 섹션 (통합·압축)
```

### 재방문 (지역 저장됨)

```
① 내 지역 카드가 히어로 대체:
   [서울권] 매우 부족 — "앞으로 4년, 필요한 집이 크게 모자랍니다"
   순위 1위/44곳 · 지난 방문보다 부족 +2,300세대 ▲
   [자세히 보기 → /zone/서울권/] [지역 바꾸기]
② 이하 동일
```

결정:
- **선택 = 저장.** 별도 저장 버튼 없음. "지역 바꾸기"로 교체
- **순위표는 폐기 아니라 강등.** SEO·기존 유저 습관 보존
- 홈 = 판정, 존 = 근거로 역할 분리. 내 지역 카드·순위 행 전부 존 페이지로 링크

## 3. 존 페이지 구성 (6섹션)

```
① 판정 히어로: [등급 배지] + 한 줄 해석 + "공급 기준 · 가격 예측 아님 · 2026.07"
   + [내 지역으로 저장] CTA
② 왜 이 판정인가 — 근거 3줄 (수치는 예시 형식, 실값은 빌드 시 계산):
   필요한 집 N (수도권 세대의 37% = 서울권 몫, 4년치)      = refq×share×16
   그동안 밀린 것 N (2010년부터 못 지은 만큼, 최대 4년치까지) = −I_now (재고면 "쌓인 것"으로 반전)
   들어올 집 N (준공예정 실측, 먼 미래는 낮춰 반영)          = supply_weighted
   → 순부족 = 필요 + 밀림 − 들어올 것 (세 줄의 합이 히어로 숫자와 정확히 일치해야 함)
   각 줄에 실측/안분 여부 괄호 표기.
   ⚠️ 현재 running_shortage()는 최종값만 반환 — 분해값(I_now, demand_sum,
   supply_weighted)을 함께 반환하도록 바꾸고 calc()가 r에 실어야 한다. JS 미러 동일.
③ 언제 들어오나 — 분기별 입주 타임라인 (기존 byq 차트 재활용)
   + "가장 몰리는 분기" 강조. 여유 존이면 "이때가 유리" 한 줄
④ 어느 단지가 들어오나 (기본 접힘) — 기존 앞으로/최근 목록 2개 통합
⑤ 이 숫자의 한계 (신설): "가격을 맞히는 지표가 아닙니다 — 금리가 크게
   움직이면 공급 신호는 묻힙니다." + 방법론 상세 접힘 (기존 '어디서 왔나' 흡수)
⑥ 주변과 비교하면 — 같은 시도 존 3~4곳 미니 카드 (등급 배지 + 순부족)
```

결정:
- ①→②의 서사가 등급의 신뢰를 만든다. 등급만 던지지 않는다
- 단지 목록은 접힘으로 강등 — 실수요자 1차 질문에 부차적
- ⑤ 한계 섹션은 실제 검증에 기반한 차별점 — 신뢰 자산
- 존 페이지의 저장 CTA는 SEO 직접 유입자를 홈 재방문 루프로 넣는 입구

## 4. 재방문 동작

localStorage 키 `agong_myzone`:
```json
{"z":"서울권","savedAt":"2026-07-31",
 "last":{"tot":465831,"rank":1,"grade":"매우 부족","seen":"2026-07-31"}}
```
- 지역 선택 또는 존 페이지 저장 버튼 → 기록
- 홈 로드 시 현재 계산값과 `last` 비교 → 변화 표시 → `last` 갱신
- 파싱 실패·없음 → 조용히 첫 방문 상태. 서버 전송 없음, 개인정보 없음
- 존이 데이터에서 사라진 경우(생활권 개편) → 저장 삭제 후 첫 방문 상태

## 5. 카피 원칙

- 서비스 용어(순부족·러닝재고·적정물량) 대신 유저 언어(필요한 집·밀린 것·들어올 집)
- 모든 숫자에 출처 성격 표기: 실측(HUB) vs 추정(세대수 안분)
- 한계를 먼저 밝힌다 — 검증으로 확인된 문장만 쓴다
- '암산' 워딩 금지 (기존 정책 유지)
