## 리뷰 세션

### sw.js VERSION 번호 체계 정리

**증상.** `2a74af9`(등급 라벨 사다리, PM 결정)가 `VERSION`을 **v107 → v102로
되돌렸다.** v102는 하루 전 `ae4af7f`가 이미 쓴 번호라, 서로 다른 두 배포가 같은
캐시 키를 갖게 됐다.

```
2a74af9  08-15  v102   등급 라벨 사다리 한 칸 (PM 결정)   ← 되돌아감
5cebd56  08-15  v107   지역 표 스크립트를 /zone/zone.js 하나로
843a31d  08-15  v106   지역 카드 빈 회색 블록 제거 + GA 옵트아웃
8be06b1  08-15  v105   지역 페이지의 '0은 자료 없음이 아니다'
ba16678  08-15  v104   2차 코드리뷰 확정 12건
2a360f7  08-14  v103   문서 4페이지(faq·about·privacy·404)
ae4af7f  08-14  v102   전체 디자인 검수 4건               ← 첫 v102
```

**원인.** 번호 체계 자체가 아니라 **병렬 세션이 각자 자기 로컬 값을 보고 +1을
하다 충돌한 것**이다. 하루에 v102~v107이 나온 게 그 증거다.

**심각도 — 낮지만 0은 아니다.**

기능상 대체로 무해하다. `CACHE = aptweather-${VERSION}`이고 activate가 현재 키가
아닌 캐시를 전부 지우므로, 값이 달라지기만 하면 무효화는 된다. 이번에도 sw.js
본문이 바뀌어 브라우저가 업데이트를 감지했고 install이 `cache:'reload'`로 다시
담았다. 다만 둘이 남는다:

1. **같은 번호 + 같은 본문이면 업데이트가 아예 감지되지 않는다.** 지금은 우연히
   본문이 달라 넘어갔다. 번호를 되돌리면서 본문까지 같아지는 회차가 나오면 그
   배포는 SW 갱신이 안 된다.
2. **번호가 순서를 못 말한다.** "사용자가 `aptweather-v102`를 물고 있다"는 로그를
   봐도 8/14인지 8/15인지 알 수 없다. 디버깅 때 걸린다.

**선택지** (판단은 리뷰 쪽에 맡긴다)

| 안 | 내용 | 평가 |
|---|---|---|
| A | 내용 해시로 자동 생성 | 충돌이 원천적으로 없다. sw.js는 손으로 편집하는 파일이라 생성 단계를 새로 만들어야 한다 |
| B | 날짜 기반(`v2026-08-15a`) | 순서가 읽힌다. 같은 날 두 번이면 접미사에서 같은 충돌이 다시 난다 |
| **C** | 현행 유지 + 단조 증가 테스트 | **권고.** 커밋된 직전 값보다 반드시 커야 한다는 시험 하나면 되돌아가는 걸 push 전에 잡는다 |

C를 권하는 이유: 원인이 "체계가 나빠서"가 아니라 "세션이 병렬이라 서로의
최신값을 못 봐서"인데, C가 정확히 그 지점을 막는다. A는 더 근본적이지만 sw.js
생성 파이프라인을 새로 만드는 비용이 문제 크기에 비해 크다. 이 저장소가 이미
여러 곳에서 쓰는 '테스트로 잠그기' 방식과도 맞다.

**개발 쪽 현재 상태.** `zone.js`는 내용 해시를 단 URL(`/zone/zone.js?v=888ad96a`,
`make_sido_pages.zone_js_src`)을 써서 VERSION에 의존하지 않는다. 그래서 이번에
v108로 올리지 않고 v102를 그대로 뒀다 — 번호를 또 건드리면 같은 충돌을 한 번 더
만들 뿐이다. 체계가 정해지면 그때 맞춘다.

**마감**: 없음.
