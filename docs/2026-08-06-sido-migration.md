## 새 구조

### 지역 20곳
`전국` `수도권` `지방` (집계 3종) + 17개 시도.
경계·이름이 국토부 통계와 정확히 같다. 표의 열 순서는 `sido_zones.ORDER`.

### 산식 — 정본은 `tools/sido_zones.py` 하나
```
I_now      = Σ_{최근 16분기} (준공 − 멸실 − 적정)
미래공급    = Σ_{k} 착공(k − 12분기) × 0.958
누적순부족  = 적정 × H − 미래공급 − I_now
```
- **리드타임 12분기(3년)·전환율 0.958은 실측값**(전국 연간, 12개월 완비 연도).
  변동계수 0.138로 k=2(0.208)·k=4(0.239)보다 뚜렷이 안정적.
- 착공·준공은 **같은 통계표의 두 열**이라 오차가 같은 방향으로 걸린다.
- 창의 기준점은 오늘이 아니라 **준공 실적의 마지막 완결 분기(L)**. 오늘을 쓰면
  아직 안 끝난 분기의 준공 0이 들어가 재고가 한 분기치 적정만큼 깎인다.
- `H`는 착공 자료가 닿는 데까지 동적 결정(현재 12분기 = 3년).

### 적정물량 — 상수로 **고정**
```
전국 95,000 = 수도권 50,000 + 지방 45,000        (분기, 호)
서울 18,700 / 경기 25,500 / 인천 5,800           ← 수도권 50,000을 세대수 비중으로 분할
부산 6,000 울산 2,000 경남 6,000 대구 5,000 경북 5,000 광주 2,700 전남 3,000
대전 2,200 충남 3,500 충북 2,700 전북 2,500 강원 2,600
세종 600 / 제주 1,200                            ← 세대당 원단위 추정(백 단위 반올림)
```
- 기준표 상수가 **국토부 통계 스케일**임을 확인했다: 합계 연 380,000호 vs 국토부 아파트
  준공 실적 평균(2011~2025) 연 325,816호 = 0.86배. 15년 평균이 적정의 86%면 만성적
  소폭 부족 — 기준표의 전제와 맞는다.
- ⚠️ **매 갱신마다 세대수로 재계산하지 말 것.** 적정물량은 기준선이지 데이터가 아니다.
  잣대가 해마다 흔들리면 시계열 비교가 깨진다. 테스트가 합계 항등식을 지키고 있다.
- ⚠️ `GRADE_CUTS` 마지막 컷은 **0.0**이다(−0.5 아님, 2026-08-02 변경분).
  옛 메모리·문서에 −0.5로 적힌 것은 전부 틀렸다.

### 데이터 배선
| 요소 | 소스 |
|---|---|
| 재고(과거) | `STATS.준공` — 국토부 주택건설 준공실적, 2010.08~, 시도별 월별 |
| 미래 공급 | `STATS.착공` — 2011.01~, 3년 시프트 × 0.958 |
| 멸실 | `STATS.아파트멸실` — 시도 연간(4로 나눠 씀) |
| 가격 | `ADV.monthly` — 매매(`ma`)·전세(`je`)·월세(`wo`) 변동률, **지역 20개가 우리 구성과 정확히 일치** |
| 점수 | `ADV.sido` — 빌드 시점에 계산해 실어 둔다. 화면은 읽기만 한다 |

⚠️ **KOSIS는 값 0을 `-`로 준다. 시리즈의 `null`은 결측이 아니라 진짜 0이다.**
시도 합계 ÷ 전국이 모든 연도에서 정확히 1.00으로 확인했다. 대구 2023년 하반기 착공
0은 사실(미분양으로 착공 중단). **건너뛰지 말고 0으로 다룰 것.**

### 홈 통합표
행=기간, 열=시도 20곳, 칸=공급 세대수 + 배경색.
- 기간 표기: 월 `17.1` / 분기 `17Q4` / 연 `2017`. **기본 분기.**
- 과거 칸 = **세로 3등분**(왼쪽부터 매매/전세/월세), ±2%가 만색.
  **±3%로 넓히지 말 것** — 최근 서울이 진한 건 실제로 공급부족이라서다(사용자 확인).
- 미래 칸 = 적정물량 대비 부족분 **단색**, 100%p가 만색.
- **최소 진하기 0.13** — 값이 정확히 0.00일 때만 무색. 흰 칸은 오류처럼 보인다.
- 굵은 줄은 **미래가 처음 섞이는 행** 앞. 연 모드에서 2026년은 실적 2분기 + 추정
  2분기라 줄이 그 앞에 오고 `±`가 붙는다.
- 표는 **월 단위로 짓고 위로 합친다**(`tbBuild` → `tbAgg`). 합친 달 수 `n`을 들고
  다녀야 부분 기간(2029년 2분기치)의 적정물량이 같은 비율로 줄어든다.
- 표두 지역명이 곧 `/zone/{지역}/` 링크다.

## 작업할 때 주의

1. **점수를 화면에서 다시 계산하지 말 것.** `ADV.sido`를 읽는다. 이중구현을 되살리면
   `check_dual_calc`가 감시하던 사고(홈과 상세가 다른 숫자)가 돌아온다.
2. **홈과 지역 페이지의 표 시작점을 같이 옮길 것.** `index.html TB_FROM`(2017.01)과
   `make_sido_pages.TABLE_FROM`(2017Q1)이 짝이다. 한쪽만 고치면 숫자를 맞춰보는
   사람이 어긋난 걸 본다.
3. **`data-core.js`는 홈 즉시 로드분**이다. `permits`에 하위 키를 추가하면 아무도
   안 막아준 채 홈 페이로드가 커진다(`split_data.BUILD_ONLY_PERMITS`에 등록할 것).
   준공·착공은 표가 그리는 구간(2017.01~)·지역(20곳)만 실려 있다.
   현재 117.7KB, 상한 180KB를 테스트가 지킨다.
4. **`sw.js` VERSION을 올릴 것** — 안 올리면 옛 화면이 캐시에 남는다(현재 v59).
5. **커밋은 즉시.** 병렬 세션이 서로 커밋을 흡수한다. `git add -A`는 금지, 자기 파일만.
6. 배치 실패가 보이면 **GitHub Actions 인프라 장애를 먼저 의심**할 것. 2026-08-06에
   Pages 3회 + 감시 1회가 `Internal Server Error occurred while resolving actions/checkout@v5`,
   `나쁜 IP: URLError`로 실패했다 — 코드 문제가 아니었고 빈 커밋 재실행으로 풀렸다.
