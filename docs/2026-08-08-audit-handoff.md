## 1. ⚠️ git 이력을 재작성하고 force push 했다 — 클론을 반드시 새로 맞출 것

696개 커밋 **전체의 SHA가 바뀌었다.** 옛 클론으로 작업하면 다음 두 가지가 일어난다.

- push가 거부되거나(non-fast-forward),
- 억지로 밀면 **제거한 인명이 이력에 되살아난다**(옛 커밋을 다시 올리는 것이므로).

받아오는 법 — 로컬에 **커밋 안 한 변경이 없는지 먼저 확인**하고:

```bash
git fetch origin && git reset --hard origin/main && git reflog expire --expire=now --all && git gc --prune=now
```

커밋했지만 안 올린 작업이 있다면 `git reset --hard` 전에 패치로 빼 둘 것
(`git format-patch origin/main` → 재설정 후 `git am`). 옛 SHA 위에서 리베이스하려 하지 말 것.

**무엇을 지웠나**: 특정 인명이 파일 내용 28개 커밋 · 커밋 메시지 · 파일 경로 2개에
남아 있었다(그 경로는 여기 옮겨 적지 않는다 — 적는 순간 되살아난다).
전부 '기준표'/'ref'로 치환하고 경로도 개명했다. 재작성 후 내용·메시지·경로 **0건**.
저장소가 PUBLIC이고 Pages가 `tools/`·`docs/`까지 서빙하므로 **코드 주석도 서비스 안**이다
— 새 코드에 인명을 쓰지 말 것. 적정물량 표는 **"기준표"**라고 부르고 출처는
국토교통부·한국부동산원만 표기한다.

부수: 커밋 1개에 있던 개인 이메일을 `agongmap@gmail.com`으로 통일했다.

**옛 SHA 참조는 이제 깨졌다.** 커밋 메시지와 문서에 적힌 `716b0bd`·`8954833` 같은
해시는 존재하지 않는 커밋을 가리킨다. 날짜와 제목으로 찾을 것.

## 3. 이 저장소가 반복해서 걸리는 결함 세 가지 — 새 코드에서 지킬 것

### ① 갱신창 밖 이력이 굳는다
위 2번. 새 계열을 넣을 때 "과거는 언제 다시 받나"를 먼저 정할 것.

### ② 지역을 이름으로만 키잉하면 시도와 시군구가 충돌한다
같은 이름이 둘이면 **뒤 행이 앞을 덮는다**. 실제 피해: 제주(`c8` 제주도 / `c801` 제주시),
광주(`b3`·`a11` 광주광역시 / `a80404`·`a1525` 경기 광주시).

**규칙: 같은 이름이면 지역코드가 짧은 쪽(상위 행정단위)을 채택한다.**
현재 `_fetch_basic_one`·`fetch_bubble`에 들어가 있다. **새 수집 함수에 같이 넣을 것.**

### ③ 마크업(td↔th)만 바꾸고 CSS를 안 따라간다
한 회차에서만 4건 나왔다. `th`일 때 상위 셀렉터(`thead th{position:sticky}` 등)가
대신 걸어주던 속성이 `td`로 바꾸면 통째로 빠진다. 실제로 홈 표 '적정물량' 수치 20칸이
스크롤하면 사라지고 라벨만 남의 줄에 얹혔다. **마크업을 바꾸면 그 셀렉터를 grep할 것.**

부수 교훈: `role="button"`을 `th`에 주면 `columnheader` 역할이 사라져 열 머리 연결이
끊기고 `aria-sort`도 무효가 된다. 키보드 접근은 `tabindex` + `keydown`으로 충분하다.

## 4. 구조·계약이 바뀐 것

- **`ADV.permits`가 20지역**이 됐다(전국·지방 추가). `ref`(저점·고점)는 이제

  - `DS_CUM = {인허가}` — 연내 누계라 '전기 대비'가 아니라 **'전년 동월 대비'**로 견준다.

## 6.6 코드리뷰 2차(2026-08-15, 6c97ee5..HEAD 33커밋) — 커밋 30e5ca7 · 5715d0e

6각도 병렬 감사. **관통하는 주제 하나: 방어선이라고 믿던 것들이 실제로는 안 돌고
있었다.** 넷이 같은 모양이었다 — 배치 한 줄이 바이트가 깨져 push 전에 죽고 있었고,
문턱을 잠근다는 테스트가 함수 객체를 assert해 항상 통과했고, 목요일 백스톱이
재시도 체인에 취소당했고, 인명 제거가 6일 만에 되돌아와 있었다. 전부 "있다고
적혀 있으나 없는 것"이라 화면·로그로는 안 보인다. **다음 감사도 여기부터 볼 것.**

⚠️ **인명이 코드 주석·테스트로 재유입돼 라이브 공개 중이었다**(30e5ca7). 8/8
이력 재작성으로 지운 이름이 8/11~14 커밋으로 3개 파일에 돌아왔고, `tools/`가
Pages로 서빙되므로 세 URL 전부 200에 이름이 실려 있었다. 작업 트리는 고쳤으나
**이력에는 남아 있다** — 지우려면 또 한 번 재작성 + force push가 필요하고 그건
사용자 판단 사항이다. 근본 원인: 규칙이 "문서에 인명 금지"로 읽혀서, 근거를
적을 때 주석은 예외처럼 다뤄졌다. **코드 주석도 서비스 안이다.**

고친 것 중 계약이 바뀐 것:
- `SZ.PWARN_CUT = 0.95` 신설. 인허가 경고 문턱을 리터럴로 흩지 말 것 — 상수로만
  참조한다. 1.0으로 자르면 수도권(실측 pmr 1.000)이 매달 깜빡인다.
- **실데이터 테스트에 문턱 통과 여부를 단정하지 말 것.** `pytest`는 update-cloud의
  하드 게이트라, 시장이 정상적으로 움직인 날 배치 전체가 커밋을 못 한다. 실측
  여유가 전국 0.097·부산 0.025·수도권 0.050뿐이었다. 오염 탐지는 **관계**
  (얇은 곳 < 두꺼운 곳)로 쓴다 — 문턱과 무관해 안 깨진다.
- 재시도 대기는 `update-cloud-retry.yml`로 분리. **update-cloud 안에서 sleep하면
  안 된다** — 워크플로 레벨 concurrency를 잡은 채 자면 그 창의 크론이 pending이
  되고, pending은 그룹당 하나만 남아 뒤에 온 디스패치가 앞의 것을 취소한다.
  ⚠️ 이 경로는 0/3 전멸이 나야 도는 코드라 **라이브 검증이 아직 안 됐다.**
- `check_freshness.FETCH_TIMEOUT` 60 → 25. 원천 대조는 HTTP 21회 **직렬**이라
  60초면 1차만 21분, 전체 28~31분으로 `timeout-minutes: 30`을 넘겼다. 넘기면
  판정 없이 죽고 recheck가 30분을 또 쓴다. 남은 일: 268행대 파생 페이지 감시처럼
  `ThreadPoolExecutor(8)`로 병렬화하면 1차가 1분대가 된다.
- 배치 종료 코드 **19는 '락 보유자' 전용**이다. 다른 실패에 재사용하면 종료
  처리기가 락을 안 지워 이후 모든 실행이 차단된다. 새 코드는 21부터.
- `make_naver_post`는 정본만 쓴다 — `M.esc`(사본은 큰따옴표를 안 막았다)·`M.num`
  (사본은 은행가 반올림)·`SZ.AGG`·`M.unsold_warn`. 순회 상태는 초안이 실제로
  저장된 뒤에만 커밋한다.

6.5의 "사용자 결정으로 유지" 항목 정정: zone의 est 안내문 없음은 맞으나,
`sido_zones.EST` 주석이 "화면에 표시할 것"이라 적고 있어 다음 사람이 지침으로
읽을 수 있었다. 주석을 사실에 맞췄다 — **배지를 되살리지 말 것.**

미해결(판단 필요):
- 재시도 게이트가 "0/3 clean"뿐이라 자가치유 불가능한 실패(시크릿 부재·배치
  크래시)도 3회 재시도한다. 시크릿 만료 날엔 순수 대기만 70분이다.
- `naver_serp`는 API 24회를 백오프·간격 없이 직렬로 던진다. 429면 그 코퍼스가
  조용히 비어 "경쟁 글 없음"으로 오독된다.
- 지역 페이지 20장이 동일 인라인 스크립트를 20벌 굽는다(+2.2KB/페이지).

## 6.7 세션 간 요청은 파일로, 착수는 표로 (2026-08-15에 굳음)

**세션 메시지는 믿을 수 없다.** 받는 세션이 유휴면 큐에 쌓이기만 하고 깨어나지
않는다. 실행 중이어도 응답을 못 만들고 매달리는 경우를 실측했다. 그래서 전달이
필요한 것은 `docs/YYYY-MM-DD-<보낸곳>-요청.md`로 남긴다 — 각 세션이 자기 페이스로
읽고, 큐에 걸릴 일이 없다.

**다만 파일만으로는 부족하다.** 같은 날 `sw.js` VERSION 건이 메시지와 파일 양쪽으로
가서 **개발과 리뷰가 같은 수정을 각자 만들었다.** 늦게 pull 한 쪽이 자기 것을 폐기했다.
요청서에 "누가 집었나"가 없었던 게 원인이다.

**그래서 요청 문서 맨 위에 착수 표를 둔다.**

| 항목 | 집은 세션 | 시각(KST) | 상태 |
|---|---|---|---|
| … | 개발 | 08-15 | 🔨 진행중 |

- **집을 때** 세션명·시각을 적고 `🔨 진행중`으로 **먼저 커밋**한다. 작업보다 먼저다.
- **끝내면** `✅ 완료 <커밋>`으로 바꾼다.
- **문서가 통째로 끝나면** 제목에 `— ✅ 종결`을 달고 맨 위에 결론을 적는다.
  끝난 일이 미결로 남아 있으면 다음 사람이 다시 집는다(§6.6의 반복 사례).
- 표는 충돌을 **없애지 않고 보이게** 한다. 큰 건이면 집기 전에 `git pull` 한 번 더.

## 7. 손대지 않은 것

- 홈 표의 월/분기/연 **모드 간** 표시 합이 1세대 어긋나는 칸. 원장 합은 정확히 일치하고
  (실측 badQ=0·badY=0) 표시 반올림만 다르다. 어느 쪽으로 맞춰도 다른 화면과 새로 갈린다.
- 월간 시군구의 인천 신설 4구(제물포·영종·검단·서해). 원천 `A_2024_00045`에 아직 없다
  (주간표에는 있다). 값이 없는 시군구는 드롭다운에서 자동으로 빠진다 — 원천이 생기면
  자동 복귀. ⚠️ 신설 4구는 옛 중/동/서구의 1:1 후신이 **아니라** 재분할이므로
  옛 계열을 신설 코드에 붙이지 말 것.
