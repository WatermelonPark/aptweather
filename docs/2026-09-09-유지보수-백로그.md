### ⚠️ 데이터 세션에 전달 — 감시 예외만으로는 다른 왜곡이 생긴다

작업 중 `check_freshness.py`에 미커밋 상태로 들어 있는 `MERGED_FROM` 예외를 봤다.
설계가 좋다. 특히 세 겹으로 좁힌 것과, 값이 하나라도 돌아오면 예외가 저절로 꺼지는
점이 그렇다. **다만 그 예외는 병합된 달을 저장분에 남기는데, 거기에 하류 문제가 있다.**

`sido_zones._series()`는 값이 `None`이어도 **월 수를 센다**:

```python
out[i] = (a + (v or 0), n + 1)
```

그래서 2026.07을 남기고 광주·전남만 결측으로 두면, 8·9월이 들어오는 순간 그 분기의
월 수가 3이 되어 `quarterly(full_only=True)`를 **통과한다.** 실측 시뮬레이션:

```
월 유지 + 광주만 결측   서울 2026Q3 채택=True 값=300 · 광주 채택=True 값=200
월 자체를 보류          서울 채택=False        · 광주 채택=False
```

즉 광주·전남만 한 달치 공급이 빠진 채 완결 분기로 잡혀 **그 두 지역의 부족이
부풀려지고 등급이 흔들린다.** `_series`의 docstring이 경고하는 "덜 찬 분기를 실적으로
쓰면 그 지역만 공급이 낮게 잡혀 부족이 부풀려진다"가 정확히 이 경우다.

수집기에서 달을 보류하면 이 문제가 없다. 두 지역 모두 미채택이라 왜곡 대신 보수적
누락이 된다. **`MERGED_FROM` 예외 자체는 그대로 둘 값어치가 있다** — 이미 저장된
과거 달이나 수집기를 우회해 들어온 달을 두 번째 층에서 받아 주기 때문이다. 다만
그 예외에 기대어 수집기 쪽을 되돌리면 위 왜곡이 살아난다.

**남은 판단(데이터 세션).** 원천이 통합을 되돌리지 않으면 광주·전남 계열이 계속

## 1. Actions Node.js 20 지원 종료 경고 — ✅ 완료 (023f312, 개발 09-10)

**결과.** 워크플로별 실행 로그를 실측하니 경고 대상이 등재된 1건이 아니라 4건이었다.
네 액션 모두 Node 24 대응 버전으로 올렸고, watchdog 수동 실행에서 경고가 사라진 것을
확인했다.

  upload-artifact    v4 → v6  (update-cloud, 2건)
  download-artifact  v4 → v7  (update-cloud, 2건)
  setup-python       v5 → v6  (watchdog, 3건)
  checkout           v4 → v5  (publish-check / write-reminder, 각 1건)

버전은 최신이 아니라 **경고가 사라지는 최소 버전**으로 골랐다. upload-artifact v5 와
download-artifact v6 은 아직 Node 20 기본이라 경고가 남고, 반대로 upload-artifact v7 은
ESM 전환, download-artifact v8 은 압축 해제 동작 변경을 함께 떠안는다. 쓰지 않는
호환성 파괴를 미리 들여올 이유가 없다. setup-python v6 / checkout v5 는 이미 이
저장소의 다른 잡에서 무경고로 돌던 버전이다.

⚠️ 하나를 놓칠 뻔했다. watchdog 의 setup-python 이 첫 조회에서 2건으로 보였는데
(출력이 잘렸다) 실제로는 3건이었다. 치환 건수를 미리 단정하고 어긋나면 멈추는
스크립트를 쓴 덕에 걸러졌다. 같은 일을 할 때는 grep 출력 개수를 눈으로 믿지 말 것.


**증상.** 데이터 자동 갱신 워크플로 실행마다 경고가 붙는다:
`actions/upload-artifact@v4`가 Node.js 20을 타겟으로 하는데, GitHub이 2025-09-19부로
Node 20 지원 종료를 예고하고 러너가 강제로 Node 24로 올려 돌리는 중이다.

**왜 백로그인가.** 지금은 경고일 뿐 배치가 정상 동작한다(2026-09-09 점검에서 확인).
다만 GitHub이 강제 실행을 끊는 시점이 오면 **데이터 배치가 통째로 멈춘다.**
그날 고치면 늦다 — 주간 갱신이 하루 이틀 빠지는 걸로 끝나지 않을 수 있다.

**할 일.** 워크플로들의 `actions/upload-artifact`(그리고 같은 경고가 붙는 액션이 있으면
함께)를 Node 24 대응 버전으로 올린다. 올린 뒤 실제 배치 1회가 성공하는 것까지 확인.

**확인 방법.**
```bash
gh run list --limit 5
gh run view <run-id>   # ANNOTATIONS에 Node.js 20 경고가 없어야 한다
```
