# PM: 타겟 사용자의 통계 루틴 — 리서치와 요청 (2026-08-17)

타겟 사용자 집단(사용자가 속한 부동산 스터디 커뮤니티)은 **매달 같은 공개 통계를
같은 순서로 따라 보는 루틴**이 있다. 그 루틴에서 겪는 불편을 실측했고, 상당 부분을
우리가 이미 풀고 있다는 것을 확인했다. 남은 것은 확인 1건과 배치 1건이다.

⚠️ **표기 규칙.** 이 문서와 후속 작업 어디에도 특정 인물·강의·유료 콘텐츠를 출처로
적지 않는다(저장소 공개, 하드 룰). 아래 불편은 전부 **정부 통계 화면 자체의 사실**이라
출처 없이 검증 가능하다. 우리가 만드는 것은 공개 통계를 보는 화면이지, 누군가의
해석이나 강의 내용이 아니다.

## 리서치 근거

**① 키워드 빈도** — 최근 강의 전사 108편(2026년분, 로컬 비공개 아카이브)에서
통계 주제별 언급 파일 수:

| 주제 | 파일 수 |
|---|---|
| 입주물량 | 82 |
| 금리 | 80 |
| 인허가 | 63 |
| 미분양 | 50 |
| 전세가율 | 48 |

**② 최신 월간 브리핑(2026-08) 실측** — 루틴 순서: **시도별 매매·전세·월세 상세
→ 인허가 물량 → 입주 물량**. 그 과정에서 나온 불편 네 가지(전부 정부 화면의 사실):

1. **발표 시차** — 같은 지표인데 통계청(KOSIS) 화면이 더 보기 편한데 늦게 올라와서,
   불편한 부동산원 화면을 먼저 본다.
2. **행정구역 개편으로 표가 깨졌다** — 광주·전남 통합, 인천 구 분리 이후 정부 화면에서
   **광주 단독 값이 아예 안 나온다.** 구 단위 숫자를 손으로 더해 광주 값을 복원해서
   보고 있다. "도표 맞춰보는 입장이면 되게 불편"한 상태.
3. **권역 묶음 불일치** — 정부 화면의 권역 구분이 보고 싶은 단위와 안 맞는다.
4. **찾기 자체가 어려워짐** — "예전엔 그냥 떴는데 지금 찾기가 복잡해졌다."

## 우리 현황 대조 — 대부분 이미 있다

| 루틴 항목 | 아공맵 | 비고 |
|---|---|---|
| 시도별 매·전·월 | ✅ 통계 시장동향 주간·월간 | 월간에 전세·월세 포함 확인 |
| 인허가 | ✅ 투자지표 (반기별) | 루틴은 월 단위로 봄 — 단위 차이 |
| 입주물량 | ✅ 투자지표 (분기별, 착공 추정 포함) | |
| 미분양 | ✅ 지역 페이지 + 통계 | |
| 전세가율 | ✅ /jeonse-ratio/ | |
| **광주·전남 분리** | ✅ **20개 단위에 둘 다 유지 중** | **정부 화면에는 없는 것** |

**가장 큰 불편(②)을 우리는 이미 풀고 있다.** 정부 화면에서 사라진 광주 단독 값이
아공맵에는 그대로 있다. 이게 이 사용자 집단에 대한 우리의 가장 강한 차별점이다.

## A. 데이터 세션 — 경계 유지 가능성 확인 (중요)

**질문: 원자료가 통합 단위로 발표되기 시작해도 우리가 광주·전남 분리를 유지할 수
있는가?** 지금 분리돼 보이는 게 옛 데이터의 관성인지, 앞으로도 지킬 수 있는 구조인지.

- 국토부·부동산원 발표가 통합(전남광주)으로 바뀌면 어느 시점부터 우리 시계열이 끊기나
- 구·시군 단위 원자료로 옛 경계를 **자동 합산 복원**할 수 있나(사용자들이 손으로 하는
  그 계산을 우리가 대신) — 가능하다면 '기존 경계 기준' 표기와 함께
- 인천 구 분리도 같은 관점에서 점검
- 결론이 "지금은 문제없음"이어도 좋다 — **언제 깨질지**를 알아두는 게 목적이다.

## B. 개발 세션 — 통계 탭 '월간 루틴' 동선

새 지표를 만드는 게 아니다. **이미 있는 것의 배치 문제다.**
매달 발표 직후 "시도별 매·전·월 → 인허가 → 입주물량 → 미분양"을 끊김 없이 한 흐름으로
볼 수 있는 동선이면 된다. 구현 형태(탭 순서 조정이든, '월간 루틴' 진입점이든)는
개발 판단에 맡긴다. 홈 개선 3건과 독립이며 급하지 않다 — A 확인이 먼저다.

## 마케팅 각도 (요청 아님, 기록)

"정부 화면에서 광주 공급량이 사라졌다 — 여기서는 계속 따로 본다"는 콘텐츠 각도가
성립한다. 통계 화면의 사실만 말하면 되므로 출처 규칙과 충돌하지 않는다.
커뮤니티에 직접 알리는 방식과 시점은 대표 판단 영역이라 여기서 정하지 않는다.

## A 회신 — 데이터 세션 (2026-08-26)

**결론: 지금 문제없고, 원천이 통합으로 더 가도 복원할 수 있다. 다만 깨지는 조건이
하나 있다.**

### ① 지금 분리돼 보이는 게 관성인가? → 아니다. 원천이 여전히 분리 제공한다

우리 등급 산식이 쓰는 **공급 4계열은 광주·전남이 시도 단위로 그대로** 나온다(실측):

| 계열 | 원천 | 광주·전남 |
|---|---|---|
| 인허가·착공·준공 | KOSIS(국토부) | ✅ 22개 지역 목록에 `광주`·`전남` 독립 행 |
| 미분양 | R-ONE | ✅ `광주>계`, `전남>계` |
| 분양 | R-ONE | ✅ `5대광역시…>광주`, `기타지방>전남` |

**재편이 일어난 곳은 시세 계열(R-ONE 주간·월간)뿐**이다. 거기서도 통합은 *상위 노드가
하나 생긴 것*이지 하위가 사라진 게 아니다 — `전남광주` 아래 `전남광주>광주`,
`전남광주>전남`이 그대로 있다. 즉 **정부 화면(웹 UI)에서 안 보이는 것**이지 API
원자료에서 사라진 게 아니다. 사용자들이 손으로 더하는 이유는 화면 문제다.

### ② 우리 구조가 왜 견뎠나 — 그리고 언제 깨지나

우리 매핑은 계층 전체 이름이 아니라 **마지막 조각**을 지역 키로 쓴다
(`full.rsplit('>',1)[-1]`). 그래서 상위에 `전남광주`가 끼어들어도 `광주`는 계속
`광주`로 잡힌다. 이번 재편을 무사히 통과한 게 이 설계 덕이다.

**깨지는 조건은 이것 하나다: 마지막 조각이 겹치는 행이 생길 때.** 지금은 충돌 0건이지만
구조적으로 안전하진 않다 — 예컨대 `경기>동부1권>광주시`는 '광주시'라 다행히 안 겹치는데,
원천이 이걸 '광주'로 줄이면 그날로 경기 광주시 값이 광역시 광주에 섞인다.

> **감시 추가 완료(2026-08-26, `4a3d6c7`).** 매 회차 원천 지역 목록에서 우리 20개
> 키와 마지막 조각이 겹치는 행이 2개 이상인지 검사한다(`check_region_collisions`).
> 겹치면 어느 행들인지까지 말한다. 시점·합계 검사로는 원리적으로 못 잡던 경로다 —
> 그때는 시점도 합계도 맞고 값만 틀린다.

### ③ 자동 합산 복원 가능한가? → 가능하다 (실측으로 확인)

원천이 통합 단위로만 발표하게 되더라도, 하위 시군구 합으로 옛 경계를 정확히 되살릴 수
있다. 2026.06 미분양으로 검산했다:

| 지역 | 시도 소계 | 하위 합 | 차이 |
|---|---|---|---|
| 광주 | 1,245호 | 5개 구 합 1,245호 | **0** |
| 전남 | 2,649호 | 22개 시군 합 2,649호 | **0** |
| 인천 | 4,204호 | 10개 구 합 4,204호 | **0** |

**단, 물량(호·세대)만 그렇다.** 지수·비율 계열(매매지수·전세가율)은 단순 합산이 안 되고
세대수 가중이 필요해서, 복원하려면 가중치 출처를 하나 더 붙여야 한다. 지금은 필요 없다 —
원천이 하위를 주고 있어서다.

### ④ 인천 구 분리

인천은 시도 단위 행이 그대로라 우리 20개 지역에는 **영향 없다**. 신설 구
(검단·제물포·영종·서해구)는 하위 계층에서만 나타나고, 우리가 인천 구 단위를 쓰는 화면은
없다. 시군구 지도(`data-sgg`)를 인천 구 단위로 확장할 때 다시 볼 사안이다.

### 요약

- **지금 끊길 위험 없음.** 공급 4계열은 시도 분리 유지, 시세는 하위 노드 유지.
- **B(동선 작업)를 A 때문에 미룰 이유 없다.** 개발 세션 진행 가능.
- **차별점은 사실이다** — 정부 화면에서 사라진 광주 단독 값을 우리는 계속 보여준다.
  다만 정확히 말하면 "원자료엔 있는데 화면에서 못 찾는 것을 우리가 대신 꺼내 보여준다"다.
  마케팅 각도로 쓸 때 이 표현이 사실에 더 가깝다.
