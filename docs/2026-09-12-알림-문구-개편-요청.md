# PM → 개발 세션: 자동 알림을 받는 사람의 말로 다시 쓴다 (2026-09-12)

| 항목 | 집은 세션 | 시각(KST) | 상태 |
|---|---|---|---|
| ① 워크플로 이름 정리(메일 제목) | 개발 | 09-12 | 🔨 진행중 |
| ② 배치 리포트 본문 재작성 | 개발 | 09-12 | 🔨 진행중 |

## 발단

대표님이 자동 알림 메일을 받고 "무슨 뜻인지 모르겠다"고 하셨다. 실물을 확인해 보니
정당한 지적이고, 세 가지가 겹쳐 있다.

**진단 한 줄. 알림이 "기계 안에서 무슨 일이 있었나"를 적고 있고, 받는 사람이 알아야 할
"내 사이트는 괜찮은가, 내가 뭘 해야 하나"를 안 적고 있다.**

만든 사람은 러너와 채택 로직을 알기 때문에 이 문장이 읽힌다. 받는 사람은 그 맥락이
없으므로 읽히지 않는다. 알림은 만드는 쪽이 아니라 받는 쪽 기준으로 써야 한다.

## ① 메일 제목에 읽을 수 없는 글자가 있다

워크플로 이름이 GitHub 실패 알림 메일의 제목에 그대로 들어간다.

```
[WatermelonPark/agongmap] Run failed: 데이터 자동 갱신 (클라우드 冗長) - main (8da30e9)
```

`冗長`은 일본어 표기다. 한국어로는 '용장'이라 읽지만 쓰이지 않는 말이고, 뜻하려던
것은 '이중화'다. 대표님이 메일 제목부터 막히신 것이 당연하다.

**바꿀 것.** 괄호 안은 내부 사정이라 제목에 필요 없다. 사람이 읽는 이름으로 짧게 간다.

| 파일 | 현재 | 바꿀 이름 |
|---|---|---|
| `update-cloud.yml` | 데이터 자동 갱신 (클라우드 冗長) | **데이터 자동 갱신** |
| `watchdog.yml` | 데이터 신선도 감시 (배치 실패 알림) | **데이터 최신 여부 점검** |
| `publish-check.yml` | 발행 확인 (알림 이슈 자동 닫기) | **블로그 발행 확인** |
| `write-reminder.yml` | 발행일 알림 (블로그) | **블로그 발행일 알림** |
| `update-cloud-retry.yml` | 데이터 갱신 재시도 대기 | **데이터 갱신 재시도** |

⚠️ 이름을 바꾸기 전에 **표시 이름으로 워크플로를 참조하는 곳이 없는지 확인**해 달라.
`gh run list --workflow=watchdog.yml`처럼 파일명으로 부르는 곳은 안전하지만,
재시도 워크플로가 표시 이름으로 상대를 찾고 있으면 조용히 깨진다.

## ② 배치 리포트가 내부 용어로만 되어 있다

지금 매 회차 이렇게 나간다.

```
### 아공맵 배치 2026-09-11 21:52 KST
- ✅ 러너 2/3 clean · 채택 주간 2026-09-07 / 월간 2026-07 / 공급 2026Q2
- ✅ 테스트
- ✅ 지역페이지
- ✅ 지표페이지
- ✅ 이달의 통계
- ✅ 사이클 리포트
- ✅ 공유카드
- ✅ 커밋·푸시 (5개 파일)
- ✅ IndexNow 제출
- ✅ 감시 최근 실행 09-11 01:57 KST (19시간 전)
```

`러너`, `clean`, `채택`, `IndexNow`, `감시`는 전부 우리끼리 쓰는 말이다. 그리고 열 줄을
다 읽어도 **"그래서 내가 뭘 해야 하나"가 어디에도 없다.**

### 바꿀 형식 — 첫 줄이 결론, 둘째 줄이 할 일

**정상일 때 (짧게):**

```
### ✅ 데이터 갱신 정상 · 2026-09-11 21:52

사이트가 최신 데이터로 갱신됐습니다. 하실 일 없습니다.

주간 시세 9월 7일 · 월간 통계 2026년 7월 · 공급 2026년 2분기 기준
```

**멈췄을 때 (무엇이 멈췄고 화면이 어떻게 되는지부터):**

```
### ⚠️ 데이터 갱신 중단 · 2026-09-11 21:36  @WatermelonPark

**사이트는 정상입니다.** 다만 9월 5일 데이터에 멈춰 있고 새 데이터가 반영되지
않았습니다.

**하실 일: 없습니다.** 세션에서 원인을 확인하고 고칩니다.
사흘 넘게 이 메일이 계속 오면 그때 알려 주세요.

**무슨 일인가:** 새로 바뀐 코드가 검사를 통과하지 못해, 숫자가 틀어진 데이터가
사이트에 올라가지 않도록 반영을 멈췄습니다. 막은 것이지 고장 난 것이 아닙니다.
```

### 용어 대응표 — 이 말로 바꿔 달라

| 지금 | 바꿀 말 |
|---|---|
| 러너 3/3 clean | 정상이면 **쓰지 않는다**. 실패 시에만 "통계청에서 데이터를 받아오지 못했습니다(3번 시도). 접속이 막힌 것으로 보이며 다음 회차에 다시 받습니다" |
| 채택 주간 … / 월간 … / 공급 … | 주간 시세 9월 7일 · 월간 통계 2026년 7월 · 공급 2026년 2분기 기준 |
| 테스트 / 지역페이지 / 지표페이지 / 이달의 통계 / 사이클 리포트 / 공유카드 | 정상이면 한 줄로 합친다("사이트 화면 갱신 완료"). 개별 단계는 실패한 것만 이름을 밝힌다 |
| 커밋·푸시 (5개 파일) | 사이트 반영 완료 |
| IndexNow 제출 | 검색엔진에 새 내용 알림 완료 |
| 감시 최근 실행 … (19시간 전) | 정상이면 **쓰지 않는다**. 이상할 때만 "점검 작업이 30시간째 돌지 않았습니다" |
| 배포 중단(코드 회귀) | 새 코드가 검사를 통과하지 못해 반영을 멈췄습니다 |

**원칙 두 가지.** 정상일 때는 확인된 항목을 나열하지 않는다(읽을 것이 없어야 정상이다).
실패는 반대로 **무엇이 안 됐는지 이름을 밝힌다** — "일부 단계 실패"는 알림이 아니다.

⚠️ 단계별 ✅ 나열을 지우더라도 **실행 로그 링크는 남긴다.** 세션이 파고들 입구가
필요하고, 그건 화면 요약(`GITHUB_STEP_SUMMARY`)에 지금처럼 자세히 남겨도 좋다.
줄이는 대상은 메일로 나가는 본문이다.

## ③ 정상 회차에 메일을 보내지 않는다 — 이게 가장 중요하다

지금은 리포트 끝에 `@$OWNER` 멘션이 **항상** 붙어서, 정상이든 아니든 매일 메일이 간다.
하루 한 통씩 "다 괜찮다"는 메일이 오면 사람은 곧 열어 보지 않게 되고, **그러면 진짜
경보도 같이 묻힌다.** 이 저장소는 이미 같은 교훈을 겪었다 — `watchdog.yml` 주석이
"오경보가 쌓이면 진짜 경보도 같이 묻힌다"고 쓰고 있는데, 그 원칙을 정상 알림에는
적용하지 않았다.

**바꿀 것.** 코멘트는 지금처럼 매 회차 남기되(기록은 그대로 쌓인다), **멘션은 조건부로
붙인다.** 멘션이 없으면 메일이 가지 않는다.

```
멘션을 붙이는 경우 = 배치가 실패했거나, 점검 작업 이상이 감지됐을 때
그 외(정상) = 코멘트만 남기고 조용히 지나간다
```

### 이렇게 해도 '조용한 정지'는 안 생긴다

`update-cloud.yml` 주석이 걱정하는 것이 "조용한 정상과 조용한 정지가 구별되지 않는
것"이고 그래서 매 회차 보고를 넣었다. 그 우려는 타당하지만 **멘션을 떼도 방어선이
그대로 남는다.** 지금 구조는 서로를 지켜보게 되어 있다.

| 어떤 사고 | 누가 잡나 | 메일 가나 |
|---|---|---|
| 배치가 실패 | 배치 자신 → 멘션 | ✅ 간다 |
| 배치가 성공하는데 데이터가 안 나감 | 점검 작업(watchdog)이 뒤처짐으로 잡음 | ✅ 간다 |
| 배치가 아예 안 뜸 | 점검 작업이 뒤처짐으로 잡음 | ✅ 간다 |
| 점검 작업이 안 뜸 | 배치가 30시간 규칙으로 잡음 → 멘션 | ✅ 간다 |
| 정상 | — | ❌ 안 간다(의도) |

**침묵이 곧 정상이라는 뜻이 되게 만드는 것**이 목적이다. 지금은 침묵도 소음도 둘 다
정보가 없다.

### 주 1회 안심 메일은 넣어 달라

침묵이 계속되면 "이게 도는 게 맞나" 싶어지는 것이 사람이다. **월요일 회차 한 번만
멘션을 붙여** 지난주 요약을 보낸다. 주 7통이 1통이 되고, 살아 있다는 신호는 남는다.

```
### ✅ 지난주 데이터 갱신 요약 · 9월 6일~12일  @WatermelonPark

7회 모두 정상이었습니다. 사이트는 최신 데이터로 돌고 있습니다.
```

실패가 섞인 주면 그 횟수와 날짜를 적는다. 구현이 번거로우면 "월요일에는 무조건
멘션" 수준으로 단순하게 가도 좋다 — 요약 집계까지는 필수가 아니다.

## 범위 밖 — 건드리지 말 것

- **블로그 발행 알림 이슈**(`[발행] 2026-09-11 주간 시세`)는 그대로 둔다. 제목이
  이미 명확하고 대표님이 실제로 쓰고 계신 흐름이다.
- 감시·재시도의 **판정 로직과 임계값**은 손대지 않는다. 이번 건은 문구와 알림
  발송 조건이지 동작 변경이 아니다.

## 검증

- 워크플로 이름 변경 후 **실제 실행 1회**가 정상으로 돌 것(이름 참조가 깨지지 않았는지)
- 정상 회차 코멘트에 멘션이 **없을 것**, 실패 회차 코멘트에 멘션이 **있을 것**
- 실패 시 본문에 "사이트 영향"과 "하실 일"이 각각 한 줄로 들어갈 것
- 기존 테스트 통과

## 왜 지금인가

대표님이 알림을 못 읽는 상태가 계속되면, 우리가 아무리 정교한 감시를 만들어도
**마지막 1미터에서 전달이 실패한다.** 감시의 가치는 사람에게 닿는 지점에서 결정된다.
