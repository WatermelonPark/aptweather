# 등급 컷 재조정 — 데이터 세션 → PM 세션 인계 (2026-08-15)

세션 간 메시지가 유휴 세션에서 처리되지 않아 파일로 남긴다.
**결정은 PM 세션에서 한다.** 이 문서는 결정에 필요한 사실과 계산만 담는다.

## 발단

사용자 지적: "전국·수도권·지방 모두 상세를 열어보면 벌건데 '다소 부족'이라는 게 이상하다.
기준을 좀 더 높여잡아야 할 것 같다."

**착시가 아니다.** 전국 순부족비 0.60은 *앞으로 3년 필요량의 60%가 순부족*이라는 뜻이다
(순부족 686,396세대 / 3년 필요 1,140,000세대). 지역 페이지 분기 표에서도 미래 12분기의
'적정 대비'가 27~103%(대부분 40~60%대)로 깔린다. 그런데 라벨은 "다소 부족 — 부족하지만
심하진 않습니다"다. **산술이 말하는 크기와 문구의 온도가 어긋난다.**

## 왜 지금 이렇게 돼 있나 (건드리기 전에 알아야 할 것)

컷은 임의로 정한 값이 아니라 **가격 실측에 묶여 있다**. `sido_zones.py:52-55` 주석이 근거다 —
순부족비 밴드별 *이후 16분기 물가차감 실질 상승률*:

| 순부족비 밴드 | 이후 4년 실질 상승률 |
|---|---|
| 0 미만 | −0.3 ~ −1.2% |
| 0 ~ 0.5 | +0.13% |
| **0.5 ~ 1.0** | **+2.58%** |
| 1.0 이상 | +10.22% |

마지막 컷이 −0.5가 아니라 0.0인 것도 여기서 나왔다(비율 0이 실질 손익분기).

**그래서 핵심 긴장은 이것이다** — 라벨은 *공급 산술*을 설명하는 말인데("필요한 집이 크게
모자랍니다"), 컷은 *가격 결과*로 잘려 있다. 0.5~1.0 구간은 공급 산술로는 "많이 모자람"이지만
가격 역사로는 "완만"이었다. 이번 위화감의 뿌리가 이 어긋남이다.

**컷을 옮기면 라벨이 공급 산술과 맞아떨어지는 대신, 위 실측과의 연결이 끊긴다.**
그 교환을 받아들일지가 PM 판단 지점이다.

## 컷 후보와 결과

집계 3곳을 한 칸 올리려면 g3 컷이 **수도권 0.58 이하**여야 한다.
경계에 딱 붙이는 건 피했다 — pwarn에서 배운 것처럼 문턱에 값이 걸치면 매달 깜빡인다.

- **A·B는 요구를 못 채운다** — 수도권(0.58)이 여전히 '다소 부족'에 남는다.

  빈 칸 자체가 오류는 아니지만, 5단계 중 하나가 비어 보이는 화면을 받아들일지는 판단이다.
- **D는 12곳이 '부족'**으로 몰린다 — 현재의 '9곳 한 등급' 쏠림을 다른 쪽으로 옮기는 셈이다.

D 기준 개별 결과: 서울 1.39 → **매우 부족**, 제주 1.79 → 매우 부족, 지방 0.62 / 전국 0.60 /
부산 0.60 / 수도권 0.58 / 전북 0.55 → **부족**, 경기 0.17 → 균형, 인천 −0.19 → 공급 여유.

## 대안 — 컷을 안 옮기는 길

사용자는 컷 이동 방향으로 이어가자고 했으나, 기록을 위해 남긴다.
**문구만 고치는 선택지**가 있다. 실측 근거를 지키면서 온도만 맞추는 방식이다:
`make_sido_pages.py:44`의 g2 설명 "부족하지만 심하진 않습니다"가 특히 약하게 읽힌다 —
이걸 "3년 필요량의 절반 이상이 모자랍니다"처럼 **수치를 말하는 문구**로 바꾸면
라벨을 안 건드리고도 어긋남이 상당히 줄어든다.

## 바꿀 때 실제로 손대는 곳 (조사 완료)

생각보다 좁다. **JS 미러 동기화 부담은 없다** — 등급은 파이썬에서 계산돼 데이터에 구워지고,
홈은 `TB_GRADE`로 라벨만 매핑한다(`index.html:2810`). 옛 작업목록의 'JS 미러 등급 대조'는
현재 구조에 해당 없다.

1. **`tools/sido_zones.py:55` `GRADE_CUTS`** — 정본 한 줄. 위 실측 주석(52-54행)도 함께 고쳐야
   한다. 근거가 바뀌었는데 옛 근거가 남으면 다음 사람이 그걸 믿는다.
2. **재생성** — `update_adv_data.py --seed-sido` → `split_data.py` → `make_sido_pages.py`.
   API 키 불필요.
3. **자동으로 따라오는 것** — 홈 지도·표·순위, 허브(`zone/index.html`), 지역 20장,
   네이버 초안(`make_naver_post.py`가 `GRADE_LABS`·`zone_order`를 읽음).
4. **테스트 수정 필요** — `test_sido_zones.py:91-94`가 경계값을 직접 박고 있다
   (`M.grade(1.5)=='g4'` 등). 컷을 바꾸면 여기도 같이 바꿔야 하며, **이 테스트가 깨지는 걸
   확인하는 게 컷이 실제로 반영됐다는 증거**다.
5. **sw.js VERSION 범프** — 홈·지역 화면이 바뀌므로.

## PM 세션에 남기는 질문

1. **D(1.2, 0.55, 0.25, 0)로 갈 것인가**, 아니면 다른 컷인가.
   집계 3곳을 올리려면 g3 컷 ≤ 0.55가 사실상 강제다.
2. **'다소 부족'이 당분간 빈 등급이 되는 걸 받아들이는가.** 대안은 5단계를 4단계로 줄이거나,
   라벨 이름 자체를 재배치하는 것(예: g2를 '부족', g3을 '심각한 부족'으로).
3. **가격 실측 근거를 뭐라고 대체할 것인가.** 지금 컷의 정당성은 그 표에서 나온다.
   컷을 옮기면 "공급 산술 기준으로 잘랐다"는 새 근거를 코드 주석과 '산출 방법'에 써야 한다.
   아공맵이 파는 게 계산법의 투명성이므로, 근거 없이 숫자만 바뀌면 그 자산이 깎인다.
